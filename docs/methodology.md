# 数据搜集方法论（5阶段）

## 概述

学术竞赛中的数据搜集应遵循"**先自动化、再搜索、最后人工**"的降级策略，每个阶段产出明确，可追溯。

---

## 阶段1：定义变量与口径

在搜集前**必须**明确：

| 项目 | 示例 |
|------|------|
| 变量英文名 | `public_charging_piles` |
| 中文含义 | 公共充电桩保有量 |
| 单位 | 台 |
| 时间口径 | **年末保有量**（非年度新增量） |
| 空间范围 | 30省（剔除西藏及港澳台） |
| 时间范围 | 2016-2023 |

> ⚠️ "年末保有量" vs "年度新增量" 是最常见的口径陷阱，搜到数据后必须核实。

## 阶段2：官方API / 数据库优先

优先使用可编程访问的官方数据源：

| 数据类型 | 推荐来源 | 方法 |
|----------|---------|------|
| 宏观经济（GDP/增加值） | 国家统计局API | Python脚本自动抓取 |
| 能源消耗 | CEADs数据库 | 下载CSV |
| 人口/面积 | 国家统计局年鉴 | API或下载 |

**产出**：高覆盖率（通常90-100%）的核心数据CSV

## 阶段3：Web搜索补缺

对API搜不到的变量，用Web搜索逐年逐省搜集。

### 搜索策略（从粗到细）

**第一轮 — 广覆盖**
```
搜索词："{YEAR}年 各省 {指标} 保有量"
目标：找到包含多省排名/表格的文章
```

**第二轮 — 逐省定点**
```
搜索词："{省名} {指标} {YEAR} 保有量 台"
目标：从省政府官网、省统计公报中找精确数字
```

**第三轮 — 站内搜索**
```
目标网站：行业网站（如 in-en.com）的站内搜索
方法：浏览器自动化
```

### 停止规则
- 连续3个省搜不到 → 停止该年份
- 某年份数据极少 → 跳过
- 口径不匹配 → 宁可留空也不入库

**产出**：带来源URL的数据CSV + 搜索日志

## 阶段4：人机协作深挖

利用不同类型的 AI Agent 协作搜集：

```
任务组织型 Agent：准备任务文档与补缺策略
        ↓
执行型 Agent：按任务文档逐省逐年系统搜索
        ↓
合并去重 → QC → 入库
```

**关键**：给 AI Agent 的任务文档要标准化（参见 [templates/task-spec-template.md](../templates/task-spec-template.md)）

**产出**：补充数据 + 更新的来源台账

## 阶段5：QC入库合并

### 单条检查
- [ ] 有 `source_url`，可点击打开
- [ ] 单位正确（"万台"→"台"）
- [ ] 口径匹配（保有量 ≠ 新增量）
- [ ] 来源分级标注（A/B/C）

### 整体检查
- [ ] `province + year` 不重复
- [ ] 非空记录数与源表一致
- [ ] 合并后行数不变

**产出**：最终交付面板 + 数据质量报告

---

## 搜索失败的替代方案

| 情况 | 应对 |
|------|------|
| 分省数据搜不到 | 改用全国数据作为时间控制变量 |
| 某些年份无数据 | 缩短面板时间范围 |
| 某变量全面缺失 | 换用可获取的替代指标 |
| 只有Top10省份 | 做子样本分析，论文说明 |
