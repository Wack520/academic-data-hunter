# README Banner and First Release Design

**Date:** 2026-04-16  
**Scope:** stronger GitHub first impression via hero/banner asset, README hero polish, and a first public-launch release artifact

## Goal

Increase the repository's public appeal and professional polish by improving what a first-time GitHub visitor sees in the first 10-20 seconds.

## Changes

1. **Banner / social preview asset**
   - Create a repository-owned banner with the core message: provenance-first, auditable datasets, evidence packs, benchmarked delivery.
   - Store it in the repo so it can be reused in README and future social/release contexts.

2. **README hero polish**
   - Add the banner near the top.
   - Add a compact value statement that explains the repo's job-to-be-done.
   - Add clearer jump links for proof, use cases, and contribution.

3. **First release notes**
   - Write a `v0.1.0` public launch note focused on differentiation, included capabilities, proof points, and next milestones.
   - Create a draft GitHub release rather than immediately publishing it, so the user can still edit wording later.

## Success criteria

- README has a more memorable hero section.
- A reusable banner asset exists in the repository.
- A release notes document exists and a draft GitHub release is created.
- Local verification passes and the latest commit is pushed.
