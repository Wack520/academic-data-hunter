# Why This Is Not Just Another Agent Framework

## The short answer

Because generic agent orchestration is not the hard part anymore.

What stays hard in real research work is:

- source quality
- provenance
- reproducibility
- reviewability
- delivery discipline

This repository is built around those constraints.

## What generic agent demos usually optimize for

- chat UX
- tool-calling breadth
- autonomy
- workflow flexibility

Those are useful, but they do not guarantee trustworthy research outputs.

## What this repository optimizes for instead

| Layer | This project focuses on |
|---|---|
| collection | official-source-first workflow |
| provenance | source registry + row-level metadata |
| validation | QC + registry consistency |
| delivery | evidence pack |
| reliability | benchmark/eval score |
| integration | API + MCP tool surface |

## The positioning in one sentence

> This is a provenance-first data and reliability layer for research agents.

## Why this matters

If an agent helps you find numbers but cannot show:

- where they came from
- whether they match your registry
- whether weak sources were cross-checked
- whether the run is good enough to trust

then you still do not have a serious research workflow.

That is the gap this project fills.
